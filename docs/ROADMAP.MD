## ❌ Descartado

Con el motivo, para no volver a evaluarlo dentro de seis meses. Son decisiones de alcance, no temas pendientes.

| Idea | Motivo |
|---|---|
| Guías paso a paso de auditoría de redes | Fuera del alcance definido en [`guides/StyleGuide.md`](../guides/StyleGuide.md): se explica el mecanismo, no la receta |
| Herramientas concretas para desanonimizar dispositivos | Igual que la anterior. El repositorio sirve para entender la propia exposición |
| Reseñas y comparativas de productos | Envejecen en meses y el repositorio se convertiría en otra cosa |
| Noticias y novedades del sector | Un repositorio de explicaciones no compite con un feed |
| Tutoriales de configuración (montar una VPN, instalar Home Assistant) | Ya existen mil, y bien hechos. Aquí se explica **por qué** funciona, no cómo instalarlo |
| Sección de programación / código | Diluye la tesis. Si hace falta código, va incrustado en el artículo que lo necesite |
| Publicar un artículo en un solo idioma | La biblioteca es bilingüe: un artículo no se publica hasta que existen sus versiones ES y EN |
| Anunciar los próximos temas | Los artículos se anuncian al publicarse, no antes |

## Cómo usar este archivo

1. **Al empezar algo**, añádelo a 🔨 En curso. Máximo tres.
2. **Al publicar**, quítalo de En curso y añádelo a ✅ Publicado con la fecha y el enlace a las dos versiones.
3. **Al descartar una idea de alcance**, añádela a ❌ con el motivo escrito. El motivo es la parte útil.

> **Al editar:** las tablas de estado están arriba y son compartidas. Todo lo demás existe en dos idiomas: si tocas una parte, tócala en los dos sitios o quedará desincronizada.

### What this document is

A living document with **what is being written, what has been published, and what has been deliberately ruled out**.

### ❌ Discarded

With the reason, so it does not get re-evaluated in six months. These are scope decisions, not pending topics.

| Idea | Reason |
|---|---|
| Step-by-step network auditing guides | Outside the scope set in [`guides/StyleGuide.md`](../guides/StyleGuide.md): explain the mechanism, not the recipe |
| Specific tools for deanonymising devices | Same as above. The repository exists to help understand your own exposure |
| Product reviews and comparisons | They age in months and the repository would become something else |
| Industry news and announcements | A repository of explanations does not compete with a feed |
| Setup tutorials (build a VPN, install Home Assistant) | A thousand already exist, done well. Here we explain **why** it works, not how to install it |
| A programming / code section | It dilutes the thesis. If code is needed, it goes inline in the article that needs it |
| Publishing an article in only one language | The library is bilingual: an article is not published until both its ES and EN versions exist |
| Announcing upcoming topics | Articles are announced when they are published, not before |

---

### How to use this file

1. **Starting something**: add it to 🔨 In progress. Three at most.
2. **Publishing**: remove it from In progress and add it to ✅ Published with the date and links to both versions.
3. **Ruling out a scope idea**: add it to ❌ with the reason written down. The reason is the useful part.

> **When editing:** the status tables are shared and live at the top. Everything else exists in two languages: if you touch one part, touch it in both places or it will drift.
